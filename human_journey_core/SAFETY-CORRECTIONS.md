# World Wrap Safety Corrections — 0.18.1

Status: automated build and isolated safety validation passed; manual acceptance and production enablement are not claimed.

Independent per-world server configuration in `<test-world>/serverconfig/human_journey_core-world-wrap.toml` (restart required; do not edit production):
```toml
[world_wrap]
enabled = false
log_crossings = true
arrival_inset_blocks = 0
[earth_protection]
enabled = false
```

Both settings default off, including missing settings on upgrades. Existing user-configured values remain respected. If an older world already explicitly enabled physical wrapping, startup is refused until protection is explicitly configured and its hooks pass verification; the feature is never silently enabled or downgraded to unsafe vanilla travel. Protection is existing-FULL-only throughout the opted-in Overworld: outside requests, missing/interior incomplete chunks and generation steps are denied; existing complete chunks remain editable/savable. It is not appropriate for a blank/generated world. Native storage supplies bounded asynchronous existing-data proofs; temporary wrap tickets are independently owned and reference-counted. No existing chunks are deleted or intentionally replaced. Outside reads are unavailable air/empty fluid and outside writes rejected; no placeholder chunk is registered or saved.

Wrapping remains inactive unless protection has passed its exact-runtime hook/startup checks. Protection without wrapping contains players and riding groups at the Earth edges. It does not wrap north/south. Movement packets are checked after main-thread dispatch and server-side Entity.move is clipped as well. All riders are retained; no dismount/recreate. Direct position writes into unavailable boundary space are rejected for entities already added to the world. An externally bypassed displacement uses a validated whole-group inside anchor or existing-only nearest same-side recovery; recovery is not diagnosed as a seam crossing. Legacy NBT positions are not silently replaced by entity-construction defaults. If no safe recovery exists, the server stops rather than allowing outside exploration or guessing a landing position.

**Explicit prototype limitation: protection reserves a 16-block inner loading band on all four Earth edges.** Canonical stored coordinates remain X=[-12288,12288), Z=[-6144,6144), but protected readable space is X=[-12272,12272), Z=[-6128,6128). Whole riding-group movement additionally retains one-block collision clearance and its full bounding footprint. Band block/fluid reads return unavailable air/empty fluid and writes are refused; saved band terrain is not deleted or changed by the guard. This avoids synchronously demanding edge chunks whose lighting dependencies extend outside the imported Earth. No north/south wrapping is added. This reduces accessible edge space and requires explicit manual acceptance.

Normal exact desired seam destinations are preferred with arrival_inset_blocks=0. Exact targets inside the reserved band are held rather than silently moved inward. A zero-inset configuration therefore protects the boundary but is not a generally usable exact-seam crossing configuration. For separate manual testing only, setting arrival_inset_blocks=32 allows an explicitly reported inward adjustment; this is a safety fallback and is NOT exact 24576-block displacement. Y/Z, native movement snapshots, orientation, UUIDs and inventories are retained on successful transfer. Holding stops outward X movement, not the survival simulation. Diagnostics show canonical versus actual arrival and adjustment. The whole-group footprint and native loading dependency radius are validated before tickets or transfer.

Limits: at most4 pending groups,16 entities/group,25 target chunks/81 dependency chunks/job,200-tick deadline;32 active disk reads/1024 queued/4096 cached proofs per map;10-second per-read timeout. Temporary registered tickets last241ticks maximum, are nonpersistent and removed on success/failure/cancel/stop. Mount/source changes cancel preparation. No waiter intentionally remains unresolved. A missing dependency may prevent an exact crossing; the group remains inside. Legacy players outside without any safe recovery may require restoring/repositioning in an expendable copy before enabling protection.

`/hj wrap status` (admin level2): protection requested/active/ready, effective wrap availability, pending work/tickets and LOADING / HELD / CROSSED / FAILED with crossed=true/false, actual/source/target, canonical destination and any fallback adjustment. Xaero visual wrapping is absent and unchanged. No production datapack/geography/progression migration.

The isolated CI harness creates a NEW flat fixture world under build/safety-server, prepares known pools/chunks, shuts it down, enables protection only there, then starts a real dedicated Forge server to exercise native chunk scheduling/storage/tickets and actual vehicles with simulated player connections. It compares region chunk-entry inventories before/after prohibited requests. The harness is excluded from the runtime JAR. Simulated players have explicit fixture chunk leases instead of real client tracking; job lease cleanup is checked relative to that baseline, and fixture leases are separately released. Native storage reads may create empty region files with zero chunk records; the check compares allocated chunk records rather than file counts or file sizes. Those tests are not real-client login/tracking or gameplay acceptance. See the release report for executed results and remaining limits.
