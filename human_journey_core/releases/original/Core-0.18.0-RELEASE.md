# Human Journey Core 0.18.0 — World Wrap prototype completion report

**Physical status:** disabled-by-default, loaded-destination prototype for isolated manual acceptance. **Xaero visual status: not implemented or demonstrated.** This is not a completed continuous-world/map solution and is not recommended for production enablement yet.

1. **Baseline/version/commit:** inspected `eccefe83bf55dd5045ba190590262e0513783f68`, Core 0.17.0, datapack **0.5.24**, Minecraft 1.21.8, Forge 58.1.18, Xaero World Map 1.39.13 (exact installed hash recorded in WORLD-WRAP.md). New Core **0.18.0**, source `85b3772431c1a0d178575994d8601a9febe87296`; successful [Actions run 46063033753](https://github.com/petryshamen/minecraft-education/actions/runs/46063033753). Newer production presentation work was preserved, no production data/config/world edits or automatic installation.
2. **Actual seam:** Earth 1500 generator settings 3072 blocks per 45-degree tile, zero map offset. Read-only equatorial Anvil headers confirm X=−12288/+12287 chunks present, immediately outer chunks absent. Canonical X interval **[−12288,+12288)**; period **24576**; all valid Earth latitudes Z∈[−6144,+6144], no Z wrap, Overworld only. Saved borders are ~60 million blocks; no border/worldgen edits. Fractional overshoot and multiple periods use bounded-world modulo arithmetic. This verifies the coordinate convention, not every seam terrain surface.
3. **Physical implementation:** isolated `org.humanjourney.core.wrap` package, one main registration line, config/example/docs and one exact-target common connection Mixin. Unique root vehicle per tick; ≤16 existing members, accepted vanilla boat/chest-boat/horse-family/player roots. Whole-group preflight of topology/aliveness/ack/chunks/border/collision/support/hazards before same-level position writes. Exact authoritative server position/angle and native known-movement snapshots (known movement can differ from stored delta on client-controlled mounts); UUIDs, inventory, health/TAN state and riding links are untouched. No serialize/recreate, dismount/remount or cross-dimension transfer. Position exceptions restore all snapshots before any packets. Publication exceptions finish attempting all participant notifications and stop further wraps; ordinary join/tracking preserves committed canonical state.
4. **Native rationale:** audited Forge-patched `ServerPlayer.teleport` can veto a passenger after native root recursion has started. Avoid that partial-operation path: use public native `teleportSetPosition` for all server positions, then acknowledged `connection.teleport`/`resetPosition` and rider root packets. Wrap-only common Mixin resets vehicle baselines and drops pre-ack vehicle packets after normal main-thread dispatch. No generic movement-validation bypass, no relaxed speed checks. Exact MC/Forge version gate; no client-only class references in new runtime classes.
5. **Destination/configuration limits:** loaded full destination chunks plus collision margin are mandatory. No engine chunk requests, force tickets, generation or height changes. Unloaded/obstructed/unsupported/unsafe destination leaves the group at its current source position and retries later; no guessed rollback point/freeze. Boats need water support and unsubmerged centre; horses need supported land. Normal Minecraft view-distance loading can still generate outside imported terrain near the seam. This remains a major limitation for unattended ocean travel. Feature is disabled by default; copy the documented TOML only to a separate expendable Earth's `serverconfig`, set enabled=true there and manually prepare known existing destination chunks. Do not copy configs to production. `/hj wrap status` requires permission 2; successful logs include source/destination/group; deferred logs ≤once/200ticks/group.
6. **Xaero investigation:** bytecode checks verify coordinate-keyed leaf/branch lookup, mutable region detection/cache paths, render-time loading, separate camera/cursor and leveled cache coordinates. A global lookup modulo or duplicate render pass is not validated as read-only tiling and could misalign cursor/waypoints/selection/HJ overlays. No safe complete repeated-image API was demonstrated. **No horizontal map repetition, coordinate remapping, waypoint/overlay repetition, duplicate cache or visual-wrap switch ships.** Existing unexplored-tile behavior and all current HJ controls remain unchanged. Exact findings and a separate rendering-instance prototype recommendation are in WORLD-WRAP.md. Do not mistake physical coordinate wrapping for Google-Maps-style visual continuity.
7. **Executed automated results:** **641 tests, 0 failures**, including all 580 prior tests unchanged and 61 new tests. **18 headless Forge checks** pass: all 17 previous checks plus actual common connection Mixin transformation and native position/rotation/velocity calculation. New test categories: seam arithmetic/fast overshoot, synthetic group commit/refusal/rollback/publication, mocked native world destination/boat/horse/ack wiring, canonical indexed geography + same-ID seam feature discovery, disabled/dimension/boundedness/side-safety source checks, exact Xaero bytecode feasibility. No real entity hierarchy, inventory serialization, network session, dedicated-server world crossing or GPU tiling was executed. Synthetic body tests do not prove real boats/horse persistence.
8. **Compatibility verification:** 406 previous runtime classes are byte-identical; the only existing changed class is HumanJourneyCore registration. All existing assets/data/Mixin configurations and existing test sources/example data/schema files are byte-identical. Java 21 classes, root pack.mcmeta format 64, source parity, no dependency bundles and common-side isolation verified from final JAR. No geography IDs/polygons/discovery ledger, advancement/progression, NPC/economy or survival changes. No save migration/reset.
9. **Manual plan:** use the eight-step checklist in WORLD-WRAP.md: disabled baseline; enable only test copy; preload known destinations; both directions/fractions/latitude/return; boats 1/2 riders/chest inventories and horse/donkey; unloaded/blocked/submerged/border refusal; concurrent groups/latency/restart/reconnect/death; canonical geography/shared discovery and all protected systems. Any duplication, separated rider or movement-ack failure blocks production acceptance. Test Xaero as unchanged non-repeating behavior, not as a delivered wrap.
10. **Next step:** user manual physical acceptance first. Production-ready unattended wrap additionally needs a vetted bounded way to load existing complete destination chunks without causing generation, and validation of all relevant entity/network sessions. Visual work belongs in an independent pinned-client prototype: canonical tile keys + visual offsets, known discovered/blank fixtures at both seams/zooms, then canonical cursor/waypoint actions and discovered HJ overlay instances. No full visual success is claimed.

Source/configuration/manual guide: WORLD-WRAP.md and example-config/human_journey_core-world-wrap.toml in source archive/repository. No example datapack is needed; there is no schema/content migration. Artifacts are archived byte-for-byte under human_journey_core/releases/original/.
